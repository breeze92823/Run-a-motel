## Current state: empty base
This repo was a boat-racing game. All of it has been removed because Bowling Roll is a new theme. What is left is the base to build on: **the player, the ground, material/texture helpers, physics and the sky**, drawn by a small `main.js`. There is no HUD, no windows, no audio, no networking, no saves and no game rules yet. The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the ground (`BEACH`, `WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> sea + clouds, lighting, ground slab + colliders, player body -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, sea ripples, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Ground**: `world.js` `buildGround(scene)` (the pale cracked-sand slab with rounded edge and a shallow-water band, through `buildSlab`), `landColliders()` (the slab's convex hull + an invisible fence on every edge), `createWorld(scene)` (the sea + clouds; `.update(dt, elapsed)` scrolls the ripples, `.setSeaColor`). The slab outline is `BEACH` in config; the new lego-style lobby will replace it.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Motel world + gameplay (`src/motel`, `src/game`, `src/fx`)
A retro desert roadside motel you run. You start with the office and room 101 ($60); rooms 102..106 open at their doors (`ECONOMY.unlockRoom`). Layout + rules tunables are `LAYOUT`, `ECONOMY`, `FOOD`, `FOOD_RULES` and `CURB` in `config.js` (the motel faces +Z; office west end, rooms 101..106, locked 2nd floor 201..207).
- **Front desk (manual)**: a bus drops guests who queue at the counter. TALK (they want a room type + 1..3 nights) -> GIVE KEY at the glowing key on the ROOM KEYS board (west wall; the key flies into the guest's hand) -> TAKE $ (price x nights; bills fly onto the counter's cash pile) -> "WELCOME! · ROOM n". COLLECT CASH at the pile banks it (AUTO CASH shop item: cash flies to you). Sam (staff) runs the desk.
- **Food (3 steps each, `game/food.js`, `motel/kitchen.js`)**: stations along the office back wall behind the counter: COFFEE BAR (open from the start: cup, brew, lid), HOT DOGS (grill, bun, ketchup & mustard) and BURGERS (grill, stack, wrap), unlocked with money. Hold E per step; stations only work with an order ("NO HOT DOG ORDERS YET"). Orders: walk-in customers wait at FOOD PICKUP (west end of the counter) and pay onto the cash pile; occupied rooms call the red phone on the counter return -> ANSWER THE PHONE -> timed order -> DELIVER at the room door -> TAKE $ left at the door. Automation: AUTO machine upgrades (`autoCoffee`/`autoHotdog`/`autoBurger`) run the steps; Mia answers the phone, cooks and serves/delivers.
- **Cleaning (`game/clean.js`)**: checkout leaves a task list with visible dirt: strip sheets + make the bed (HANDS, needs a clean set from the laundry), trash (BAG), dust bunnies (VACUUM), carpet stains + sink/mirror (SPONGE), muddy footprints (MOP), toilet (BRUSH). Holding E fades the decal with particles + sounds; the room shows a CLEAN % tag over its door and a checklist inside; 100% plays a celebration (sparkles, bed bounce, announce). Cleaning tools must be picked from the hotbar (HANDS jobs switch for you). Rose does the jobs one by one.
- **Curb appeal (`game/curb.js`)**: lot litter, walkway grime, graffiti (SPONGE) and posters (HANDS) on the outside walls (`motel.wallSpots`) lower appeal; below `CURB.fewerBelow` fewer guests get off the bus, below `CURB.noGuestsBelow` nobody does and walk-ins stop, even with clean rooms.
- Also: laundry (basket -> washer -> fold clean sets; Lou), junk yard + dumpster, fountain, pool, furnishing rooms (F).
- **Furnishing + guest wealth (`src/decor/`, tunables `DECOR` in config.js; `ECONOMY.roomUpgrades = DECOR.items`)**: F / the FURNISH button opens a full-screen editor (`furnish.js` + `furnish.css`): the camera swoops to a cut-away of the room (global clipping plane at y 3.3 removes roof + ceiling), 3D orbit (drag / wheel / pinch) or TOP; left DONE / UNDO / REDO / 3D-TOP / CANCEL; top room bar (type, $regular / $richest guest, stars to the next type, required items with ✓/!, LOOKS score, which guest tiers it fits); right ITEMS (8 categories, 33 pieces, one per slot) / WALLS / FLOOR cards. Edits are a draft shown live in the room (items drop in, wallpaper rolls up, floors unroll); DONE pays only for what is new (items owned per room stay in storage, walls/floors are bought once for the motel) and celebrates a new room type / guest tier. Rules (`rules.js`, no three.js): comfort points -> stars (`starPoints`, plus `requires`: SINK OR TUB for ★3, a TV for ★4, a 3-pt bed + tub for ★5); LOOKS 0..100 = base + wall + floor + MATCH (surface tone = the furniture's dominant tone; wood is neutral) + item style; nightly = base + furniture + type + LOOKS x `stylePrice`. Guest tiers (`guestTiers`: backpacker, traveler, business, wealthy, VIP) each need ★ + LOOKS; `rollTier` weights them by attraction = best room's looks/stars + rating + cleanliness (curb appeal + dirty rooms; below `attract.dirtyBelow` the rich stay away). A fitting room earns x`payMul` and bigger tips; rich guests get outfits, a sparkle trail, fanfares (`decor/sfx.js`) and a headline at the desk. Scene side: `room.js` (per-room wallpaper/band/floor overlays in front of the baked linings, slot anchors, colliders, animations; wraps `interior.bed.set` for the King / Magic bed overlays), `models.js` (procedural furniture), `paint.js` (wall/floor painters + swatches), `thumbs.js` (card pictures rendered off screen). `index.js` `createDecor` is made by game.js (`window.__motel.decor` in dev); economy stores the furniture in use (`setRoomFurniture`, `roomEval`, `useRoomLooks`), the 'decor' save section the rest.
- `world.js`: desert pad (hole for the pool basin), dunes, mesas, highway, light-asphalt lot, sidewalk, fence + water tower, clouds; `landColliders()` = pad boxes round the pool hole + invisible fence.
- `motel/`: `paint.js` canvas painters (stucco, star fascia band, asphalt, brick, room plate, neon, wallpaper, wainscot, carpet, drapes, tile, fabric, stains); `kit.js` (`box`/`rbox` with metre UVs, cached `mat`, shared textures, palette `C`); `building.js` (shell, walkway, columns, starry fascia, balcony + broken railing, rundown 2nd floor, room doors/windows/plates/boards, stairs + barricade, soda/ice machines; static parts baked); `rooms.js` (walk-in rooms: holed front wall, wallpaper/wainscot, bed with made/used/stripped + comfy states, tiled bathroom + toilet, drapes, fridge/TV/vanity furniture, bathroom sink + mirror, dirt decals: stains, dust, mud, toilet/sink grime, litter spots); `kitchen.js` (the 3 food stations + `makeFood(kind)`); `office.js` (walk-in lobby: counter, register + cash pile, phone on the return, FOOD PICKUP plate, RECEPTION sign, ROOM KEYS board with a numbered, glowing key per room, OUR GUESTS + HELP WANTED corkboards, ceiling fan); ## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
