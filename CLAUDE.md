## Current state: empty base
This repo was a boat-racing game. All of it has been removed because Bowling Roll is a new theme. What is left is the base to build on: **the player, the ground, material/texture helpers, physics and the sky**, drawn by a small `main.js`. There is no HUD, no windows, no audio, no networking, no saves and no game rules yet. The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the ground (`BEACH`, `WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- Boxity integration (docs.bloxity.io/#html5; answers recorded in `BLOXITY_CODE_METADATA.md`: canDie false, one leaderboard, a 2x-cash rewarded ad, five ribbons, no Gems anywhere): every Boxity URL comes from `boxityEnv()` in `src/bloxity.js` (the told environment, prod fallback; never the page hostname). `bloxity.js` also does emotes (`registerFeature('emotes')`, `onEmote` -> `src/avatar/emotes.js` plays the catalogue clip on the rig, stops on move), ad breaks (`onAdBreak`: main loop pauses, `src/fx/mixer.js` mutes all four audio contexts; the mixer also applies `master_volume` / `music_volume`), screen ads (`adScreen('panel' | 'gameplay')` from the main loop), rewarded ads (`showRewarded` -> net.js `claimAdReward` -> the server verifies the token -> `economy.grantAdBoost`; Shop card from `AD_REWARD` in catalog.js, shown only when `adsAvailable()`), `LEADERBOARDS` define, chat bubbles over the local player (`onChat`), the character kit (`dressCharacter`, manual loader.js path when it returns null), friend-join toasts (`playerJoined`) and `getToken()` (sent with the join / identify; the server only trusts that). `BLOXITY_LOCAL=true` makes the dev server inject a local `window.BLOXITY_ENV` (vite.config.js).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> sea + clouds, lighting, ground slab + colliders, player body -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, sea ripples, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; the game is first person only (`MODES = ['player']`: no V key, no CAM touch button, wheel does nothing; the chase-cam code stays for if `character` is listed again); `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Ground**: `world.js` `buildGround(scene)` (the pale cracked-sand slab with rounded edge and a shallow-water band, through `buildSlab`), `landColliders()` (the slab's convex hull + an invisible fence on every edge), `createWorld(scene)` (the sea + clouds; `.update(dt, elapsed)` scrolls the ripples, `.setSeaColor`). The slab outline is `BEACH` in config; the new lego-style lobby will replace it.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Motel world + gameplay (`src/motel`, `src/game`, `src/fx`)
A retro desert roadside motel you run. You start with the office and room 101 ($60); rooms 102..106 open at their doors (`ECONOMY.unlockRoom`). Layout + rules tunables are `LAYOUT`, `ECONOMY`, `FOOD`, `FOOD_RULES` and `CURB` in `config.js` (the motel faces +Z; office west end, rooms 101..106, locked 2nd floor 201..207).
- **Front desk (manual)**: a bus drops guests who queue at the counter. TALK (they want a room type + 1..3 nights) -> GIVE KEY at the glowing key on the ROOM KEYS board (west wall; the key flies into the guest's hand) -> TAKE $ (price x nights; bills fly onto the counter's cash pile) -> "WELCOME! · ROOM n". COLLECT CASH at the pile banks it (AUTO CASH shop item: cash flies to you). Sam (staff) runs the desk.
- **Food (3 steps each, `game/food.js`, `motel/kitchen.js`)**: stations along the office back wall behind the counter: COFFEE BAR (open from the start: cup, brew, lid), HOT DOGS (grill, bun, ketchup & mustard) and BURGERS (grill, stack, wrap), unlocked with money. Hold E per step; stations only work with an order ("NO HOT DOG ORDERS YET"). Orders: walk-in customers wait at FOOD PICKUP (west end of the counter) and pay onto the cash pile; occupied rooms call the red phone on the counter return -> ANSWER THE PHONE -> timed order -> DELIVER at the room door -> TAKE $ left at the door. Automation: AUTO machine upgrades (`autoCoffee`/`autoHotdog`/`autoBurger`) run the steps; Mia answers the phone, cooks and serves/delivers.
- **Cleaning (`game/clean.js`)**: checkout leaves a task list with visible dirt: strip sheets + make the bed (HANDS, needs a clean set from the laundry), trash (BAG), dust bunnies (VACUUM), carpet stains + sink/mirror (SPONGE), muddy footprints (MOP), toilet (BRUSH). Holding E fades the decal with particles + sounds; the room shows a CLEAN % tag over its door and a checklist inside; 100% plays a celebration (sparkles, bed bounce, announce). Cleaning tools must be picked from the hotbar (HANDS jobs switch for you). Rose does the jobs one by one.
- **Curb appeal (`game/curb.js`)**: lot litter, walkway grime, graffiti (SPONGE) and posters (HANDS) on the outside walls (`motel.wallSpots`) lower appeal; below `CURB.fewerBelow` fewer guests get off the bus, below `CURB.noGuestsBelow` nobody does and walk-ins stop, even with clean rooms.
- Also: laundry (basket -> washer -> fold clean sets; Lou), junk yard + dumpster, fountain, pool, furnishing rooms (F).
- **Pacing (`game/pacing.js`, `PACING` in config.js)**: easy start, steeper later. `heat` = (open rooms - 1) x `perRoom` + franchise level x `perFranchise` (0 with one room on the first run = the plain game), set each frame by game.js `setPacing`. Demand: guests per bus `busGuests(open)` grows with the open rooms (capped by the desk queue), the bus gap `busGap` shrinks with the rating and the motel size (adverts / billboard through `economy.guestEvery`, never under `minBusGap`), RUSH HOUR buses (`rushHour`, from 3 rooms) bring extra guests. Challenge: desk patience x `patienceMul()` x the guest tier's `patience` (rich guests wait less), extra mess per checkout (`messExtra`, clean.js), lot litter / grime / graffiti / posters (`spawnMul`) and food walk-ins (`walkInMul`) come more often.
- **Furnishing + guest wealth (`src/decor/`, tunables `DECOR` in config.js; `ECONOMY.roomUpgrades = DECOR.items`)**: F / the FURNISH button opens a full-screen editor (`furnish.js` + `furnish.css`): the camera swoops to a cut-away of the room (global clipping plane at y 3.3 removes roof + ceiling), 3D orbit (drag / wheel / pinch) or TOP; left DONE / UNDO / REDO / 3D-TOP / CANCEL; top room bar (type, $regular / $richest guest, stars to the next type, required items with ✓/!, LOOKS score, which guest tiers it fits); right ITEMS (8 categories, 33 pieces, one per slot) / WALLS / FLOOR cards. Edits are a draft shown live in the room (items drop in, wallpaper rolls up, floors unroll); DONE pays only for what is new (items owned per room stay in storage, walls/floors are bought once for the motel) and celebrates a new room type / guest tier. Rules (`rules.js`, no three.js): comfort points -> stars (`starPoints`, plus `requires`: SINK OR TUB for ★3, a TV for ★4, a 3-pt bed + tub for ★5); LOOKS 0..100 = base + wall + floor + MATCH (surface tone = the furniture's dominant tone; wood is neutral) + item style; nightly = base + furniture + type + LOOKS x `stylePrice`. Guest tiers (`guestTiers`: backpacker, traveler, business, wealthy, VIP) each need ★ + LOOKS; `rollTier` weights them by attraction = best room's looks/stars + rating + cleanliness (curb appeal + dirty rooms; below `attract.dirtyBelow` the rich stay away). Scene side: `room.js` (per-room wallpaper/band/floor overlays in front of the baked linings, slot anchors, colliders, animations; wraps `interior.bed.set` for the King / Magic bed overlays), `models.js` (procedural furniture), `paint.js` (wall/floor painters + swatches), `thumbs.js` (card pictures rendered off screen). `index.js` `createDecor` is made by game.js (`window.__motel.decor` in dev); economy stores the furniture in use (`setRoomFurniture`, `roomEval`, `useRoomLooks`), the 'decor' save section the rest.

## Road, plots and other players (`src/plots.js`, `src/remoteMotels.js`, `src/remotePlayers.js`, `src/presence.js`)
A room holds 6 players (backend `ROOM_MAX_CLIENTS`, Legion `seatCap`); each owns one of `PLOTS.count` motel plots, 3 on each side of the main road, side by side (`PLOTS` in config.js; the server hands out roster `plot` 0..5, `net.myPlot()`).
- **Frames**: every client plays on ITS plot's coordinates (all of src/motel and src/game are unchanged); `plots.js` places everything else round it: `plotMatrix(k, mine)` for another plot, `globalMatrix(mine)` for the shared road block, `toMine(k, mine, x, z, yaw)` for a pose. Even slots are on the near side (the global frame = plot 0's), odd ones across the road, turned 180 degrees round the road's centre line (`LAYOUT.road.z`); `PLOTS.columns` = slot -> column, so slots 0 and 1 face each other.
- **Ground** (`world.js`): `buildGround` = the shared block (pad with a hole for every plot's pool, dunes, mesas, road, water tower; `setPlot(k)` moves it when the server's plot arrives) + this plot's `buildPlotGround` (lot, stripes, sidewalk, fence). Site landscaping outside the plot's x range was dropped (`site.js` `mine()`): the neighbours stand there. Colliders are this plot's only (players never leave their own plot + half the road).
- **Other motels** (`remoteMotels.js`): the motel builders run ONCE for an undrawn template (colliders off: `physics.withoutColliders`); its static parts are baked (`bake.js bakeMeshes`, coarse keys) and shared by all five copies; the changing parts are snapshots (pool closed/open, fountain broken/mended, door boards: shared and instanced, see "Draw-call savers"; furniture + wallpaper/floor and the junk yard: re-baked per copy on change, one per frame), plates and signs are per copy. Dressed from the roster `motel` view (backend `motelView.ts`, built from the owner's save; "" = fresh). Rooms/plates/furniture only within `PLOTS.detailRange` (`detailRangeTouch` on phones). Pool `close()` / fountain `unfix()` exist for this. ~2.4 s to build at load; ~600 extra draw calls seen from the lot.
- **Other players** (`remotePlayers.js`): base rig dressed by the Boxity character kit from the roster `outfit` key (`bloxity.canDress` / `dressCharacter(..., key)`), else the manual loader path from roster `avatar` JSON { equipped, proportions, skin } (`bloxity.avatarLook`, signed-in players), name tag, the roster `emote` (EmotePlayer), chat bubbles (`remotes.bubble(m)`, matched by username), animator from speed/grounded, dead-reckoned poses. `presence.js` sends `pose` (own-plot frame, `NET.poseEvery`) and `look` { outfit, avatar, emote }. Guests' saves are sent too (the server only shows them, never stores them).

## Draw-call savers (`src/shadowCasters.js`, `src/staticBatch.js`, `bake.js`, `lighting.js`)
- **Shadow casters** (`pruneCasters`, run on the own plot's builders at start and on the furniture every 2 s): pieces under `LIGHT.shadowMinRadius`, and pieces inside a roofed room (`INDOOR`: the guest rooms, the laundry) more than `LIGHT.indoorSunReach` behind the front wall, stop casting; the office (glass front) and the carried laundry basket keep theirs.
- **Shadow box** (`lighting.update(dt, focus, ahead)`): `LIGHT.shadowRange` half-width, pushed `LIGHT.shadowAhead` toward the camera's view and snapped to whole shadow texels (no shimmering).
- **Static batcher** (`createStaticBatcher`, started 2.5 s after loading, main.js `startBatching`): every visible opaque plain mesh under the motel / site / signs / plot ground / furniture (decor) roots is merged per map cell (`bakeMeshes` `exact` + `fold`) and its original waits on layer 31; the roots are rescanned every 2 s, so what the game adds later joins. Each frame a slice of the originals (all `watch`ed known movers: doors, beds, boards, keys, cash pile, basket, yard bags/junk) is compared with what was merged (world matrix, visibility chain, material + a folded material's colour/roughness/..., geometry, castShadow); one that changed is drawn by itself at once and its cell re-merges (one per frame); a piece unchanged for 6 s is merged again. Only `exclude`d pieces never merge (ceiling fan, washer drum, clock). Casters also become per-cell shadow proxies (positions only, one per material side) whose main-pass draw is cancelled in `onBeforeRender` (negative draw range): they draw only into the shadow map; the merged visible meshes cast none. ~0.5 ms/frame on desktop. `__game.batcher.stats` in dev.
- **Folded colours** (`bake.js` `foldable` / `fold`): plain materials (Standard/Lambert/Phong, no maps, opaque, not glowing, no `userData.k`) are merged into one shared vertex-coloured twin per lighting kind (`foldKey`: everything but the colour), the colour going into each piece's vertices (same linear value: identical look). Used by the batcher and the remote copies; glowing / textured / animated-colour materials keep their own.
- **Clouds**: the ~180 puffs are one merged mesh (`world.js makeClouds`).
- **Remote copies** are instanced (`remoteMotels.js` `instancedSet`): one InstancedMesh per shared baked mesh, instance = copy; a copy out of the camera's view (its plot box) or a part it does not show is scaled to nothing and parked on a shown copy so three.js still culls per mesh.
- **Shader warm-up** (main.js `warmShaders`, loading step 'Preparing shaders'): `postfx.compile` compiles every material in the scene (hidden too) for the current target (bloom HDR target or the screen), plus every furniture model, bed overlay, food, six guests, the folded twins and the shadow-proxy materials, then renders one frame through the bloom passes; nothing compiles later in play (checked: pool, guests, furniture, night, batcher start). ~0.4 s desktop.
- **Perf overlay** (`src/perfHud.js`): F8 in dev, `?perf` in the address in any build (phones). fps + avg/worst frame ms, game CPU ms/frame, draw calls + triangles over all passes of a frame (it sets `renderer.info.autoReset = false` and resets at frame start), GPU geometries/textures/shaders, JS heap (Chrome), canvas size/DPR/preset, batcher and road lines.
- Measured (desktop, from the lot / at the desk / overview): 2606 / 2264 / 6014 draw calls before all this, 502 / 291 / 1269 after (looking straight at the motel: 586).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
